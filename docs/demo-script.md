# Сценарий видео на 3–5 минут

## 0:00–0:40 — Задача и архитектура

Показать экран входа. Объяснить: FastAPI обслуживает API и интерфейс, PostgreSQL хранит
пользователей, диалоги и сообщения. Отдельный worker обрабатывает сохранённые запросы к модели.

## 0:40–1:40 — Вопрос и продолжение диалога

Войти, выбрать «План действий», спросить о запуске функции за две недели. В контекст
добавить состав команды и ограничения. Показать очередь/ожидание, форматирование и копирование.
Затем спросить «А какие риски у этого плана?» и показать, что модель учитывает текущую беседу.

## 1:40–2:30 — Постоянная история

Перезагрузить страницу. Затем открыть другой браузер, войти тем же пользователем и показать
сохранённый диалог. Объяснить, что данные загружаются из PostgreSQL и не зависят от localStorage.
Показать новый диалог и список последних бесед; более старые сообщения можно загрузить отдельно.

## 2:30–3:20 — Доступ и ошибки

Объяснить проверку владельца, серверные сессии, CSRF и лимиты. Показать сохранённую ошибку
провайдера в заранее подготовленном тестовом сценарии. Повторная отправка после потери
HTTP-ответа использует тот же request ID и не создаёт ещё один запрос к модели.

## 3:20–4:20 — Код и эксплуатация

Показать модели, миграцию Alembic, транзакцию сохранения и worker. Объяснить разделение
API и генерации: принятое задание не пропадёт при закрытии вкладки. Сказать, что при
неопределённом результате платного запроса автоматический повтор не выполняется.
Показать сервисы Compose, проверки готовности и команды резервного копирования.

## 4:20–4:50 — Проверки

Показать тесты изоляции пользователей, идемпотентности, сохранения сообщений и миграций.
Озвучивать только результаты реально выполненных проверок. Не показывать API-ключи,
пароли и `.env`. Само видео записывается отдельно.
